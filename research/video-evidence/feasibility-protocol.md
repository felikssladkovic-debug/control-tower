# Video clip around event — optional RAT feasibility protocol

- **Статус:** Planned experiment / optional RAT stretch goal; не выполнено.
- **Дата:** 2026-11-10.
- **Основание:** [Issue #13](https://github.com/felikssladkovic-debug/control-tower/issues/13), [research options](approaches.md), [RAT scope](../../docs/product/rat-1.0-scope.md).
- **Ответственность за приоритет:** эксперимент запускается **только при наличии времени/ресурсов**, не входит в обязательные критерии успеха RAT 1.0.
- **Цель:** показать потенциальному заказчику наглядный временной видеоконтекст события. **Не** решать задачи Computer Vision.

## 1. Гипотеза

Небольшой фрагмент очень низкого качества из специально подготовленного или разрешённого источника, привязанный к событию кофемашины, можно показать в Control Tower с минимальной новой инфраструктурой, без распознавания действий и видеостриминга в браузер.

**Противоположная гипотеза:** для достоверного поиска видео по интервалу потребуется несоразмерно сложный архив/оборудование, либо такой фрагмент практически ничего не добавит к демонстрации PACT.

## 2. Минимальный демонстрационный сценарий

1. Симулятор PACT публикует **synthetic** \`MachineBrewingStarted\` или \`MachineError\` для Accra 02 с timestamp \`T\`. Данные должны быть согласованы с заранее подготовленным тестовым видео.
2. На странице события/инцидента менеджер выбирает **«Видео около события»** или ограниченный интервал.
3. Система выбирает подготовленный фрагмент из разрешённого MP4 (в простом RAT clip можно уже заранее нарезать), ориентир окна \`T-15s…T+15s\`.
4. Пользователь видит короткий **MP4 без звука**, около **100×100 px max**, около **3 FPS**, с явно показанными camera/source, event time, clip interval, synthetic/demo flag.
5. При недоступном интервале или источнике UI показывает **«Видео недоступно»**, а не подставляет примерный клип.

**Граница моделирования:** фрагмент связан с событием как media/evidence reference; видео **не анализируется** и не создаёт derived observation о сотруднике, кнопках или рецепте. Синтетическая связь timestamp/clip — демонстрационная, не подтверждённая корреляция реального мира.

## 3. Архитектура минимального эксперимента

- Источник: 1–3 коротких MP4, снятых в постановочных условиях с правом использования, или полностью синтетические материалы (не реальные видео работников).
- Источник событий: имеющийся/планируемый simulation/replay канал RAT.
- Маршрутизация: метаданные \`eventId ↔ cameraId, clipStartUtc, clipEndUtc, clipRef, origin, availability\`; exact schema выбирается при реализации, не требуется новый универсальный тип сущности.
- Поставка media: локальный защищённый ресурс/endpoint в тестовом окружении с возможностью воспроизведения браузером.
- Трансформация: при необходимости FFmpeg offline (time slicing, ~3 FPS, resize с сохранением aspect ratio, audio off). Не необходимы MediaMTX, streaming server, GPU, ML inference, CV, NVR или custom media service.
- Хранение исходных видео и фрагментов — за пределами публичного репозитория. Небольшой **искусственный** тестовый ролик может добавляться в репо только после явного решения о допустимости бинарных артефактов.

### Если дойдём до реальной камеры

Сначала проверить **имеющийся NVR/архив**: источнику должно быть доступно прошлое время \`T-preRoll\`. RTSP live сам по себе не содержит прошлого. Если архив отсутствует, такой use-case **не** реализован простым подключением к RTSP; локальный rolling buffer — отдельное исследование/решение, не предпосылка RAT.

## 4. Переменные и проверки

| Variable / case | Test | Expected |
| --- | --- | --- |
| Window | default \`T±15s\`; alternate bounded interval | Воспроизводится запрошенный кусок и явно указаны его точные временные границы |
| Format | ~100×100 bounding box, ~3 FPS, no audio | Проигрывается в браузере, не искажает aspect ratio, звук отсутствует |
| Event mapping | Normal event vs event from another shop/device | Нет ошибочной подстановки чужого clip |
| Time alignment | event clock vs media clock offset | Offset обозначен, при неизвестном alignment связь не выдаётся за достоверную |
| No archive / missing interval | No recording for T | Честный unavailable, без подстановок |
| Source provenance | Synthetic / staged / real / unknown | Маркировка и ограничения видны; не маскируется происхождение |
| Access | Allowed manager vs unauthorized role | Доступ разрешён/отклонён, нет открытых постоянных camera URL |
| Cleanup | Delete/expire test clip | Фрагмент более недоступен после согласованного удаления |

**Метрики для lab:** число успешно воспроизведённых окон / число валидных запросов, ошибки временной синхронизации, время/размер конвертации, размер итогового MP4, время открытия в браузере, количество ручных действий по подключению источника. Не измерять CV precision/recall: распознавание отсутствует.

## 5. Минимальные acceptance criteria (только если эксперимент выбран)

- [ ] Один event → нужный ограниченный клип со стабильной временной привязкой.
- [ ] Просмотр в web UI, низкое разрешение, ~3 FPS, no audio, без заметной дополнительной инфраструктуры.
- [ ] Отражены камера, интервал, источник (включая synthetic), неопределённость синхронизации.
- [ ] Путь «нет клипа»/ошибка/нет доступа проверен.
- [ ] Фрагменты не используются для CV/inference или выводов о личности/действии.
- [ ] Протокол выполнения и наблюдаемые результаты записаны отдельно с версиями кода/окружения, командами, скриншотами без персональных данных, измерениями и ограничениями.

**Основной RAT не зависит от этих критериев:** отсутствие видео не блокирует RAT-S1, RAT-S2 или решение о переходе к MVP 1.0.

## 6. Оценка стоимости (предварительная, не измерено)

- Только подготовленные короткие MP4 + метаданные + элемент UI — относительно небольшой объём работ.
- Преобразование полного видео в фрагмент по требованию добавляет FFmpeg, обработку ошибок, синхронизацию и ограничения доступа.
- Подключение реального архива/NVR потребует исследования конкретного оборудования, прав и условий хранения.
- Прямая запись постоянного RTSP с pre-roll, операционная безопасность и поддержка нескольких объектов увеличат стоимость на порядок относительно подготовленных clips; **не включать без отдельного обоснования**.

## 7. Stop / pivot criteria

- Видеофрагмент бесполезен как демонстрация даже при ~100×100 / 3 FPS.
- Не удаётся получить корректное окно из существующего архива без сложной инфраструктуры.
- Юридические/этические риски или требования хранения превышают ожидаемую пользу.
- Функция тормозит основные RAT experiments.
- Требуется распознавание действий, постоянный видеостриминг, идентификация сотрудника либо собственный NVR: **это другой scope**, не расширение текущего по умолчанию.

## 8. Источники и границы доказательств

- [FFmpeg main documentation](https://ffmpeg.org/ffmpeg.html) — фильтрация/масштабирование/управление частотой кадров/аудио.
- [MediaMTX recorded stream playback](https://github.com/bluenviron/mediamtx/blob/main/docs/2-features/10-playback.md) — возможность программного получения интервала из архива как reference, если реально понадобится.
- [Ghana Data Protection Commission compliance](https://dpc.gov.gh/compliance/) — требования защиты персональных данных до реальных записей.

Сведения о технологических возможностях инструментов **не** являются свидетельствами работоспособности PACT или доступности архива в конкретной кофейне. **Execution status: NOT RUN.**
